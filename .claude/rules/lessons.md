# 指摘の教訓（繰り返し禁止）

ユーザーから受けた指摘の蓄積。同じ指摘を二度受けないための学習ファイル。
新しい指摘を受けたら、その場でここに 1 行追記してからコミットする。

## 文章

- ですます調で書く。常体は禁止（2026-08-08 指摘）
- 本文で太字を使わない。どこが重要かは読者の成長段階で変わるものであり、書き手が強調で固定しない（2026-08-08 指摘）
- 定義していない略語を使わない。図のラベルも同じ。RP・ARM で二度指摘を受けた。書く前に「この語は第0章の登場人物表か初出で定義済みか」を確認する（2026-08-08 指摘 x2）
- 雑な定義で片付けない。「テナントは Entra ID のインスタンス」のような、それ自体が説明を要する語で定義した気にならない。読者は Azure 初心者である（2026-08-08 指摘）
- 前提手順を飛ばさない。アカウント作成やサブスクリプション作成のような「入口」も章として書く。読者は途中から始められない（2026-08-08 指摘）

## セキュリティ

- 顧客名・実在のテナント ID・サブスクリプション ID・個人ドメインを公開リポジトリに書かない。例はダミー値にする。拒否リストは scripts/lint/structure-lint.mjs にあり、新しい実値に触れたらリストにも追加する（2026-08-08 指摘）

## 運用

- push したら CI の結論を確認する。「落ちっぱなし」に見える状態を放置しない。落ちたら次の作業より先に直す（2026-08-08 指摘）
- 検証していない手順を verified と記録しない。実測で仕様と違った例: az deployment は未登録プロバイダーを自動登録する / az keyvault create は論理削除済み Vault を自動復元する / 管理グループ操作は伝播で一時的に失敗する
